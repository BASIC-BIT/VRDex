## Required clarifications

1. **The migration contract already requires positive production admission.** Design line 46 leaves this as a question, but `scripts/event-broadcast-migration-rehearsal.ts:119` explicitly says whole-flow requires actual admission. Its protocol `start` calls the real schedule mutation at line 385 and records `real-admission` at line 431 only after acquisition and command claiming. `tests/scripts/event-broadcast-migration-rehearsal.test.ts:132` deliberately expects a failed whole-flow receipt at `protocol-lifecycle` while the production map is empty, with no `real-admission` evidence and successful cleanup. Keep that coverage and receipt meaning unchanged. Any synthetic seeded protocol exercise must have a distinct evidence scope and cannot satisfy this whole-flow gate. The current `localEventBroadcastRehearsal.ts` describes historical fixtures that never grant worker/publication authority, and exposes no existing synthetic admission operation. Adding one is a separately reviewed fixture change, with local deployment guards, manifest ownership, isolation, and cleanup preserved. The positive actual production-start scenario remains blocked on measurements.

2. **`typeof resolveWorkerAllocation` currently does not provide a typed input.** Design line 19 rightly preserves inferred mutation types, but `broadcast-capacity.mjs:7-8` has no input annotation. Its inferred resolver input is `any`; the allocation result does have a type through `parseAllocation`. Give the capacity resolver a small JSDoc input/function contract, deriving `videoPreset` from the existing `VideoPreset` or `MediaSettings` typedef in `broadcast-profiles.mjs`, and deriving its allocation result from `parseAllocation`/`WorkerAllocation`. Then `typeof resolveWorkerAllocation` is useful. Keep `mutation({args: eventMediaWorkerScheduleArgs, handler})` inside the factory so Convex infers context, validated arguments, and return values. Do not hide a type error with `any`, a broad registered-mutation return annotation, or a cast.

3. **An underscore helper filename is not a deployment exclusion.** Design line 19's fallback is misleading if it relies on the underscore. The installed Convex bundler `src/bundler/index.ts:446-477` excludes `_generated` and other specific paths, but includes ordinary `_helper.ts` files. The strongest available local evidence supports keeping the ordinary factory export in `events.ts`: existing utility exports establish precedent; Convex `src/server/api.ts:225` filters API members by `isConvexFunction`; `mutationGeneric` attaches mutation metadata to the returned registration, not to a factory that returns it. Verify analyzed function names with the project's supported codegen/local analysis flow after implementation. A generated file content comparison alone is insufficient for a type-derived API. If analysis actually rejects the helper, select a supported module placement based on that error; moving to `_helper.ts` alone does not prove it fixed the issue.

## Feasibility and scope

The closure factory is smaller and safer than module mocking here. Backend tests use Node's `mock.method` for clocks, fetch, and mutable methods; those patterns do not supply an isolated replacement for a named ESM import. `convex-test/dist/index.js:1292` uses the supplied module loader per fixture, and `resolveFunction` at line 1934 obtains the named registered function and validates its arguments/results. Returning a spread of the real module with only `scheduleEventMediaWorker` replaced therefore retains framework validation and the real handler. It does not mutate the cached production module. Keep a single named events loader helper rather than building a generic modules transformer. Both relevant test commands already load tsx, and the lifecycle `.mjs` file already imports backend `.ts` fixture helpers, so the TS helper is a supported existing pattern; the proposed `.mjs` fallback is unnecessary unless an actual import failure appears.

The bridge options addition fits its existing clock/signal dependency options. Forward the same resolver through all five calls and keep the default on each public entrypoint. `startCommand` admits dispatch before task-definition construction and releases unlaunched admission on registration/configuration failure. A default resolver rejection should therefore assert no RegisterTaskDefinition, RunTask, or launch marker, plus release and existing command-error reporting. Supply the fixture resolver to the Lambda handler's `createLambdaHandler({runBridge: ...})` dependency, not to its AWS runtime object.

Do not rewrite the narrow control-only fixture just to make all tests uniform. Its existing direct session seeding has an explicit scope and avoids pretending to test capacity admission. Tests that currently exercise scheduling should continue through the real schedule handler with injected capacity.

## Acceptance details to retain

- Keep the production measured map empty and keep the real default registrations. Never make fixture evidence IDs, database rows, RPC arguments, or environment data authorize capacity.
- Use the same resolver for fresh allocation and `validateMeasuredSnapshot(validateAllocationSnapshot(...), resolver)`, including scheduled existing-session paths. Neither snapshot validator may be removed or bypassed.
- Keep authorization, account authority, event time, output destination, open/claimed session, immutable media settings, frozen simulcast membership, profile, allocation shape, evidence, and resource-limit assertions. Existing negative tests should continue to assert their intended errors under the synthetic resolver.
- Keep independent default-entrypoint rejection tests across all 12 production configurations, real authorized Convex scheduling with no scheduling side effects, and default bridge processing of a structurally valid synthetic snapshot. For the persisted-snapshot scheduler test, compare the existing session/program/command/audit state before and after rejection so absence of new rows does not miss mutation of existing rows.
- Include a small isolation case with production and fixture `convexTest` instances in the same test: the fixture succeeds while the default still rejects. This demonstrates that the seam did not introduce shared authority.
- Preserve exact allocation assertions in capacity/Lambda tests when sharing fixture data. Equality between two calls to the same fixture resolver alone cannot detect an accidentally changed fixture allocation.
- Treat focused test and typecheck runs as implementation acceptance work. The design does not establish that all previously failing tests will pass, that Convex analysis has run, or that whole-flow migration is unblocked.

With these clarifications, implement the unit-test seam independently of the migration contract change.
